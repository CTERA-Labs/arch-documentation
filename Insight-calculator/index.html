Cost Model Overview

This calculator estimates the customer's cloud infrastructure cost for a CTERA Insight BYOC deployment - a single workload cluster running a single tenant in the customer's AWS or Azure subscription.

What's Modeled

  • Workload cluster: Kubernetes control plane, OpenSearch (3 master + N data nodes on storage-optimized NVMe instances with S3 remote-backed storage), application nodes (Atlantis, Backoffice, ArgoCD, Argo Workflows, insight-ui, agent-service, self-hosted Git, self-hosted artifact registry), Ingestor JobManagers (always-on) and a single processing TaskManager (duty-cycled per tenant).
  • Storage: OpenSearch data on instance-local NVMe (included in instance price) with a primary segment copy in S3 / Blob (remote store), application-node PVCs for Git + artifact repo, S3 / Blob Hot for input bucket and ingestor checkpoints.
  • Network: Internal load balancers, NAT Gateway, cross-AZ OpenSearch replication (when 3-AZ enabled), egress, DNS.
  • Managed services: Secrets Manager / Key Vault, KMS / Key Vault keys, CloudWatch / Log Analytics.

Key Sizing Formulas

  • Ingestor = 1 TaskManager per tenant, duty-cycled (~30% each); cost scales with tenant count, not data size. Flink state is ~100 GB per 1B files (0.1 KB/file), stored per tenant — one i8g.large covers a ~4B-file tenant.
  • Application nodes = cheapest instance fit for cluster baseline (~6.5 CPU / 24.7 GiB: platform services, ArgoCD, Argo Workflows, Atlantis, Backoffice, Keycloak + in-cluster Postgres, Gitea) + per-tenant demand (~3.5 CPU / 6.7 GiB: Flink JMs, fs-ca ingestion, UI, agent-service, MCP, PDF, reports) × 1.2 headroom.
  • OpenSearch storage = (fs_md + activity + folder_history) × (1 + replicas), using measured compressed per-doc sizes (fs_md 327 B, history 228 B, activity 771 B).
  • Data node size + count: the smallest instance in the storage-optimized ladder (i8g.large → xlarge → 2xlarge) whose local NVMe fits the data at the 85% watermark in the minimum node count; larger datasets scale out on the largest size. No EBS for data — durability via S3 remote store.
  • Activity volume = files × 0.0022 consolidated events/day (2.2M/day per 1B items, production average) × retention.
  • Folder history = tiered: daily ×7 + weekly ×4 for all folders (10% of items), then one monthly snapshot per remaining retention month for 5% of folders.
  • Replicas default to 0 — with remote-backed storage a replica is an uptime choice (shard availability during node failure/restarts), not a durability requirement. Cross-AZ replication cost applies only when a replica is enabled.

Out of Scope

  • LLM token costs for the agent service (customer-supplied API key, usage-based).
  • Initial sync ("INIT phase") burst capacity. The model estimates steady-state BAU costs.
  • Customer-side network costs outside the cluster (corporate egress to the platform, etc.).

Pricing

All rates are on-demand list prices as published by AWS us-east-1 and Azure East US at the time the calculator was built. Customers should apply their contracted, Reserved Instance, or Savings Plan discounts to the exported BoM.
